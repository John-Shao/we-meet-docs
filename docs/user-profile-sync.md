# WeMeet → Docs 用户姓名同步

## 数据归属

WeMeet 通讯录是显示姓名和简称的来源。Docs 的用户行是这两项资料的本地副本，所有成员列表、评论、文档作者、搜索和用户接口继续使用同一用户表。两个服务用 `sub` 关联，不按邮箱或姓名合并账号。

同步只涉及 `full_name`、`short_name`，不改变 Docs 用户 ID、邮箱、语言偏好、文档权限或历史记录。尚未使用 Docs 的通讯录用户不会因为扫描被创建，也不会收到消息或邮件。找不到对应 WeMeet 身份的独立 Docs 用户计入 `unmatched`，资料保持原样。

## 统一校准

WeMeet 的 `sync_docs_profiles` 命令通过受服务间令牌保护的 `/api/v1.0/users/directory-profiles/` 接口遍历已有 Docs 身份。每页最多 100 人，使用用户 ID 游标分页，再从 WeMeet 数据库读取当前姓名并回写。全量校准覆盖历史曾用名、普通保存、批量修改以及失败期间的改名，避免依赖各业务入口的同步回调。

阿里云 Helm 配置启用独立 CronJob，每分钟运行一次。正常情况下资料会在下一次扫描后统一，已打开页面需要重新查询才能显示；这是最终一致性，不是实时推送。任务不在用户请求内访问 Docs，因此 Docs 故障不会阻塞改名。

CronJob 禁止自身重叠，单次失败最多重试两次，总执行期限为 300 秒；后续计划运行再次从当前资料扫描，修复漏同步。大型部署应按实测扫描耗时调整 `backend.docsProfileSync.schedule` 和模板执行期限，确保一轮能完成。失败 Job 和非零退出状态可用于现有集群告警；日志只输出数量，不输出姓名或令牌。

每批在读取 WeMeet 数据之前生成 `observed_at`。Docs 的 `meet_profile_synced_at` 只接受更晚的快照，重复请求和较旧的迟到结果不能回滚姓名。同步主机应保持正常时钟同步。每个回写用户必须有状态确认，缺少、重复确认或无效分页会令任务失败。

首次权威同步之后，Docs 的 `User.save()` 在行锁内保留最新已同步姓名及标记，防止旧 OIDC、旧会话票据、邀请或摘要任务中的名字写回去。同步端点使用带版本条件的数据库更新。今后新增修改姓名的代码不得绕过这一约束直接使用 `QuerySet.update()`；后台校准负责这两个字段的权威写入。

权威快照必须同时提供两个字段，明确空字符串表示清空；缺失字段拒绝处理。旧的建号/登录路径只用于尚未同步的身份引导，不能覆盖已纳入同步的资料。

## 上线

1. 先部署 Docs 后端，并执行迁移 `0035_user_meet_profile_synced_at`（现有部署的 migrate Job 自动执行）。
2. 部署 WeMeet 后端及 Helm 配置。阿里云 `backend.docsProfileSync.enabled` 已设为 `true`；其它环境默认关闭，可启用 CronJob 或用外部调度器定期执行命令，不依赖 Celery Beat。
3. 在 WeMeet 后端容器内执行 `python manage.py sync_docs_profiles` 可立即修复历史姓名；也可等待第一轮 CronJob。正常输出为 `updated/stale/missing/unmatched` 计数。
4. 在通讯录改名后，不做邀请或重新登录，等待下一轮成功任务，再打开 Docs 成员列表、评论或用户页面检查姓名。

无需重发邀请、重建权限或更新 Android / Web 前端。回滚时先关闭 CronJob，再回滚后端；不用删除既有权限数据。
