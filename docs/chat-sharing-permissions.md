# 聊天分享授权协议

Android 原生分享拆分为“分享到聊天”“链接分享”“成员与权限”。聊天卡片继续使用 `doc-card` v1。发送者的卡片直接显示当前会话授权“可阅读 / 可评论 / 可编辑”，点击可调整授权，不重发卡片。尚无会话授权或查询失败时保留“会话权限”入口，不猜测权限。PC Web 页面不改，但实际权限与 Android 一致地由 Docs 后端计算。

## 可调整的聊天授权（当前协议）

- Android 使用 Meet `POST /api/v1.0/im/doc-chat-access/`，请求 `{doc_id, cid}` 查询，附 `role: reader | commenter | editor` 保存。成功读取或保存后同步同一会话中的同文档卡片，返回会话时重新查询。
- Meet 校验当前会话成员资格；修改时从 IM 读取成员名单，解析接收者身份，以登录用户的 `sub` 作为 `actor_sub`。客户端提交的操作者和成员名单均不可信，不转发。
- Meet 调用 Docs S2S `POST /api/v1.0/documents/chat-access/`：`{doc_id, cid, actor_sub, role?, users?}`。Docs 查询要求可读取文档，修改还要求 `accesses_manage`，仅可编辑文档不足以转授权。
- 响应 `{scoped: true, role, complete, can_manage}`；未建立聊天授权时 `role: null`。保存必须同时确认 `scoped`、匹配角色及 `complete: true`，否则保留草稿并允许重试，不能降级调用旧授权接口。
- 授权来源按 **文档 + 会话 + 分享者** 区分。同一分享者在同一会话发出的同一文档卡片共用设置，不把消息里的静态字段当作当前权限。
- `DocumentChatShare` 记录会话授权设置；`DocumentAccess` / `Invitation.chat_permissions` 记录独立权限基线、各聊天来源与已计算角色。现有 `role` 存储它们的最高权限，现有列表查询和文档权限检查无需分叉。
- 本聊天来源可从编辑降为阅读；独立授权、其他聊天来源、祖先文档/团队权限及链接权限不会随之降低。邀请转换为用户授权时保留来源。手动保存成员/邀请会清除来源追踪，将该次手动设置作为后续基线；旧卡片无来源记录的授权也作为基线保留。
- 查询卡片不会补发、重新授权或恢复已删除的成员。保存只处理当前会话成员；离群成员既有的直接权限不自动收回，新增成员不自动获权，需再次保存或分享。
- 新版文档分享流程也使用此协议，默认阅读；重复分享同一文档到同一会话会设置同一个聊天来源。卡片发送和授权仍分别记录及重试。

## 兼容接口（此前只追加授权）

1. Android 选择会话后确认授权类型，默认 `reader`，可选 `editor`。无 `accesses_manage` 能力时只发送卡片，不申请新增授权。
2. 卡片发送成功后，Android 请求 Meet `POST /api/v1.0/im/grant-doc-access/`：`{doc_id, cids, role}`。
3. Meet 以调用者身份读取当前会话成员，解析成 `{sub, email}`，调用 Docs `POST /api/v1.0/documents/grant-access-for-users/`：`{doc_id, users, role, actor_sub}`。`actor_sub` 必须取自已认证的 Meet 用户，不接受客户端指定。
4. Docs 使用现有 S2S token 鉴权，并检查该操作者对文档的 `accesses_manage` 能力。仅阅读或编辑文档的能力不能用于给别人授权。

角色仅接受 `reader` / `editor`。成功返回 `{granted, role, complete: true}`；`granted` 为新增或升级条数，已有足够权限时为 0，仍可完整成功。无法解析的收件人导致 `complete: false`。Meet 还会将会话成员查询或身份解析失败计入不完整结果。

已有直接授权和邀请只升级、不降级：阅读 < 评论 < 编辑 < 管理 < 所有者。继承或链接提供的权限继续由既有权限模型计算。授权给分享当时的会话成员，不建立群与文档的动态绑定；后来入群不会自动获权，退群也不会自动撤销直接授权。聊天分享不会修改文档的链接访问范围。

## 失败与兼容

- 卡片发送和授权分别记录进度。授权失败可单独重试，不重发已确认送达的卡片；重复授权幂等。
- 显式角色请求必须收到相同 `role` 和布尔值 `complete: true`，不能把旧服务只返回 `granted` 视为成功。
- 未传 `role` 的旧调用保留原先只读 S2S 契约和 `{granted}` 响应，供旧客户端及会议纪要等既有服务调用继续使用。该兼容路径没有升级为新版操作者校验，应作为后续统一迁移项目处理。
- 链接分享设置仍调用既有文档更新 API；“仅已获授权用户”不新增授权，也不显示链接角色。非受限范围的角色由服务端 `link_select_options` 决定。复制的是同一文档链接，更新范围会影响已发出的链接。

## 发布与验证

依次部署 **Docs backend（执行至 `0036_documentchatshare_commenter` 迁移）→ Meet backend → Android APK**。`0036` 增加会话角色的评论选项，不更改已有授权；本次没有改动 Docs 前端。旧服务未升级时，新版 App 必须显示授权未完成，不能提示授权成功。

测试覆盖阅读/编辑往返、独立权限和多个聊天来源、手动授权、邀请转换、已删除授权只读查询、操作者权限、会话资格、可信成员解析和旧服务响应拒绝；文档成员/邀请模型做了存储服务隔离的回归测试。模拟器验证旧卡片的入口和未部署时错误态，不向真实聊天发送测试消息。真实保存及收件人跨账号读写须在两个后端部署后联调。
