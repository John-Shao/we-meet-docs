# Docs 与 WeMeet 的 UI 对齐

## 规范来源

`we-meet/src/design-tokens` 是 UI 规范的来源。Docs 已适配通用对话框、文档列表、侧栏、操作菜单和页面工具栏，保留 Cunningham 的交互、业务逻辑及文档编辑器的正文排版。

在 `src/frontend/apps/impress` 中执行：

```sh
yarn sync-we-meet-ui
yarn check-we-meet-ui
```

同步命令默认读取相邻的 `we-meet` 仓库，也可通过 `WE_MEET_DESIGN_TOKENS_DIR` 指定设计令牌目录。它生成两个需要随代码提交的文件：

- `src/cunningham/we-meet-contract.json`：颜色、文字、间距和控件规范快照。
- `src/cunningham/we-meet-ui-tokens.css`：由快照生成的 CSS 变量。

生成文件不能手工修改。`predev` 和 `prebuild` 会校验 CSS 与快照一致；相邻 WeMeet 仓库存在时，还会验证快照与源规范一致。独立 Docker 构建使用已提交的快照，不依赖另一个仓库。原有圆角、阴影和尺寸校验继续保留。

## 对话框接入

使用 `components/modal/ModalHeader` 替代各窗口独立实现的标题和关闭按钮，并在 Cunningham `Modal` 上设置 `hideCloseButton`。保留现有标题 ID、无障碍标签、关闭回调，以及忙碌时禁止关闭的约束；通过 `closeDisabled` 禁用标题栏关闭按钮。

共享标题栏作为样式作用范围标记。`we-meet-dialogs.css` 仅适配包含该标题栏的弹窗，不覆盖页面或文档正文的标题、段落与编辑器工具栏。

- 标题使用 `titleMedium`；文档名和内容使用 `bodyMedium`；说明使用 `bodySmall`。
- 标题栏和操作区使用相同的横向间距与分割线；内容区域滚动，标题和操作按钮保持可见。
- 操作按钮默认 40px；关闭按钮为 28px 盒子、20px 图标。底部按钮按内容宽度靠右排列。
- 带标签的 Input / Select 使用 `variant="classic"`，标签位于控件上方；单行控件高度为 32px。
- 普通表单直接使用 Modal 内容区的默认内边距。搜索、成员列表等齐边布局给内容根节点加 `wm-modal-edge`。
- 自带底部操作区的布局使用 `wm-modal-footer`，避免重复定义按钮间距、边距和分割线。
- 浅色与深色分别映射 WeMeet 的语义颜色，禁止继续根据旧色阶档位猜测用途。

文档相关标题可以复用 `DocModalHeader`，统一呈现“操作名称（文档名称）”、省略及完整名称提示。

## 第一批覆盖

分享文档、成员与权限、成员邀请的 Docs 回退界面、删除、导出、搜索、移动、退出文档、网络提示、恢复版本确认，以及复用 `AlertModal` 的移动确认和权限申请提示。

## 第二批覆盖

- 文档列表：标题 16px、名称 14px、日期和列头 12px，列表项最小高度 48px，长标题省略，统一卡片、留白和悬停颜色。
- 侧栏：分类导航、收藏和文档树共用语义颜色；当前项使用选中底色与文字色，键盘焦点清晰可见。保留文档树的虚拟行高度、拖拽和快捷键。
- 操作菜单：Cunningham UI Kit 与本地菜单统一使用 14px 字体、32px 最小行高、20px 图标和语义表面色；删除操作、禁用项及选中项使用对应状态颜色。
- 页面工具栏：统一按钮高度、图标盒子、间距和浮层阴影；新建按钮及其拆分菜单按钮保持等高。
- 加载和空状态：在列表内部呈现，不再通过全局样式锁住整个页面的滚动；初次加载保留内容区高度。

`we-meet-ui.css` 存放共享控件和语义颜色映射；`we-meet-pages.css` 存放页面布局。页面根节点使用 `wm-ui` 标记，弹出到 portal 的本地菜单也需要该标记。UI Kit 菜单通过其独立的 `.c__dropdown-menu` 类接入。不要将标记加到包含编辑器正文的布局根节点上。

## 第三批覆盖

- 版本历史：使用“版本历史（文档名）”标题栏与固定底部还原按钮；桌面左右分栏，窄屏上下分区，列表和预览分别滚动。保留初始版本定位、只读权限和还原确认流程。
- 引导窗口：统一标题、步骤、图标、底部按钮和主题颜色；删除会影响其他弹窗的全局滚动及底部样式，窄屏按钮按内容宽度排列。
- 编辑器浮动工具栏及菜单：统一 14px 控件字体、32px 控件高度、20px 图标、选中/禁用/焦点状态及浮层颜色；窄屏工具栏允许换行。链接输入框沿用相同表单规范。
- 附件下载风险提示：接入共享标题栏和关闭按钮。

这些专用布局使用 `we-meet-specialized.css`。编辑器样式只匹配工具栏、菜单、建议列表和链接表单，不对文档块、正文行距、用户文字颜色或标题格式设置通用 UI 字号。

## 第四批覆盖

- 评论区：浮动评论卡片、侧栏评论、回复和编辑输入区统一表面色、文字层级、圆角、边框与焦点；成员名使用 14px，时间使用 12px，发送按钮显示文字并使用 32px 控件高度。保留评论权限、筛选、回复和解决流程。
- 辅助面板：评论和目录共用 16px 标题及紧凑标题栏，内容独立滚动；目录当前项与悬停态分开，层级缩进及键盘焦点使用设计令牌，移动端面板宽度受视口约束。
- AI 提示区：提示输入、建议列表、停止按钮及错误状态统一颜色和尺寸，宽度适配窄屏，建议列表限制高度并滚动。保留请求、停止和接受结果的业务流程。
- 演示控制栏：统一浅色/深色浮层、按钮、分隔线和间距，保留翻页、全屏、关闭和首次焦点行为。

辅助界面样式位于 `we-meet-collaboration.css`，评论专用样式位于 `doc-comments/styles.tsx`。这些规则不设置文档正文或演示内容的通用字体。

第四批浏览器验收使用实际组件、内存评论存储和模拟 AI 状态，覆盖浅色、深色、375px 窄屏与低高度窗口；另用实际 `ConfigProvider` 的主题消息处理在 iframe 中验证切换主题不重载。该验收不替代线上登录、真实 AI 服务及协作同步联调。

## 验证

- 运行 `yarn check-we-meet-ui`、`yarn check-we-meet-tokens`、TypeScript、ESLint、Prettier 和修改样式的 Stylelint 检查。
- 回归链接保存/复制、成员授权和主题切换的现有测试。
- 回归菜单键盘导航、禁用项跳过、工具栏菜单项和列表日期显示；检查浅色、深色及窄屏下的长名称、菜单定位和选中状态。
- 回归版本选择、只读预览及还原确认；在实际 BlockNote 控件中验证格式操作和链接输入，在引导窗口中验证步骤切换及键盘关闭。
- 在浅色、深色、375px 窄屏与低高度窗口中检查长标题、滚动、操作按钮、表单标签、键盘关闭和焦点。
- 新增或修改主题时，确认文档正文的字号、行距和用户格式未受到对话框适配影响。

前端样式变更需要重新构建、推送并部署 Docs 前端镜像，仅拉取代码不会更新正在运行的页面。
