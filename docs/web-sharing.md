# Web 文档分享

## 入口与布局

- 分享弹窗分为“分享到聊天”和“链接分享”。WeMeet Web 宿主确认支持 `docs-sharing-v2` 后，默认打开聊天页；独立访问 Docs 时默认打开链接页。
- “成员与权限”为独立弹窗，分享页底部和文档“…”菜单均可进入。原有访问申请、历史邀请、继承权限和最后一位所有者限制保留。
- 链接分享只维护一份文档级配置。修改选项保留为草稿，点击“保存并复制链接”才提交；设置保存失败不复制，剪贴板失败提供可选中的链接。切换分享标签保留草稿，关闭弹窗丢弃未保存草稿。
- “仅已获授权用户”不提供额外的链接授权类型；用户继续使用各自已有权限。其他访问范围根据服务端 `link_select_options` 提供可阅读 / 可编辑。

## 聊天与授权

- Docs 负责展示文档和选择权限；WeMeet 复用 `ForwardDialog` 搜索会话、联系人和多选，也保留创建群聊入口。
- 分享页的授权默认可阅读，可选可编辑。无管理权限的用户只能发送卡片，不为接收人增加权限。
- 卡片发送和聊天授权分别确认。已确认发送的卡片不会在重试授权时重复发送；发送超时无法判断是否送达时，明确提示先检查聊天记录，再由用户决定重新发送。
- 授权使用已有 `/im/doc-chat-access/`，针对授权时服务端确认的会话成员。后续入群用户不会自动获得权限。相同文档、会话的授权沿用已有来源合并规则，不覆盖其他独立来源的权限。

## 邀请成员

- 宿主声明 `docs-member-picker` 后，邀请成员打开 WeMeet 公共 `DirectoryMultiPicker`。候选项来自组织通讯录，按用户 ID 排除已有成员，不要求邮箱或预先登录 Docs。
- 使用已有 `/docs/member-access/`：先读取成员 ID，再按批次提交用户 ID 和 reader / commenter / editor。保留已有权限；成功后刷新成员列表，失败用户保留选中以便重试。
- 独立 Docs 或旧宿主使用 Docs 原有可见用户搜索范围，按姓名选择、按用户 ID 直接授权。不会构造邮箱邀请；该搜索不等同于 WeMeet 的完整组织通讯录，也不能代替宿主为首次使用 Docs 的同事建立身份。
- 已存在的历史邮箱邀请仍可查看和撤销，本次移除新邀请的邮箱依赖。

## 协议与部署

| 能力 / 消息 | 方向 | 内容 |
| --- | --- | --- |
| `docs-sharing-v2` | 宿主握手 | 聊天权限选择、结果反馈、分类重试 |
| `docs-member-picker` | 宿主握手 | 通讯录多选和按用户 ID 授权 |
| `wemeet-share-doc` | Docs → WeMeet | `docId`、`title`、`role`、`canManage` |
| `wemeet-invite-doc-members` | Docs → WeMeet | `docId`、`title` |
| `wemeet-doc-access-updated` | WeMeet → Docs | `docId`，使权限相关查询失效 |

宿主校验消息 origin、当前 iframe source 和文档 UUID，并自行构造规范文档链接。`canManage` 仅控制 UI；授权接口始终在服务端校验管理权限和真实接收人。新能力必须收到握手确认，不能在握手等待期间乐观启用。

完整功能需要同时发布 `we-meet` Web 与 `we-meet-docs` 前端。复用已有身份授权和聊天授权接口，无新增数据库迁移。Android 原生页面没有改动。

## 验证

- 单元测试覆盖无邮箱用户、部分失败保留与重试、重复提交防护、消息来源校验、授权结果校验、卡片发送与授权分离、链接保存失败与复制失败。
- 两个前端执行 TypeScript / ESLint / Prettier 检查及生产构建。
- 本地浏览器使用拦截的 API 数据检查独立 Docs、跨域 iframe 握手、分享标签和公共邀请面板；未向真实会话发送测试消息或修改线上权限。
